# critical_report：执行协议

终稿逐项对照净方程与文字描述：不得把分步脱水写成额外的净脱水；涉及共价中间体时须区分中间体形成、键变化、游离产物释放与辅因子再生，缺失的释放能力应作为科学缺口返回，不能隐藏或当作已证实。

核对报告是否把局部官能团氧化误写成确定的外部氧化剂需求。缺乏整体配平、总电子变化或原子对应依据时，只能表述为未验证的化学问题；不能声称某机制因此必然不可行，也不能把计量假设升级为实测机理。

审核必须遵守工具回执的 `source_policy`。关闭来源不能被引用；仅有私有证据或没有本体证据时仍可完成报告，前提是准确标注证据范围、模型假说和缺口。空引用数组本身不是失败理由；没有取证依据的候选必须写“未经过本体证据核实”，不能冒充已报道活性。不得为了满足默认公共证据流程而访问关闭来源。

本阶段执行本插件自己的事实边界批判与确定性报告协议：先形成 `06_critique.json`；只有 PASS 才发布 `07_final_report.json`、同源 Markdown 与 Mermaid。REVISE 必须停在批判阶段，不得把部分本体命中包装成最终成功报告。

只审查本轮产物，不新增机制或候选，不联网、不读文件、不使用历史答案或评测材料。

先调用 `enzyme_entity_run_context(stage="critical_report")`，逐项检查：共享辅因子是否被误写为相同活性；家族或相关蛋白的先例是否被归给具体蛋白；所有 `reported_*` 事实、实体候选和已报道路线步骤是否引用本轮已回读 Evidence；事实、机制类比与模型预测是否分开；目标反应活性是否仍明确为未验证；每条路线是否完成七项闭合与辅助步骤检查。正好提交六个 `check_id`，不能漏项或重复。证据优先按一次批量调用回读，常规回读预算为 10 次，系统硬上限为 16 次，至少预留 4 次给 `enzyme_entity_critical_report_commit` 及校验修正；不得因目标活性未验证而返回 `UNVERIFIED`。

检查通过表示证据与未知项表达合规，不表示路线已经实验验证。若机制账本含本体证据启发的弱假说，还要检查它是否经过 Evidence 回读、化学门控、机制聚类和统一排序；实体或关系命中以及 `weak_hypothesis_required=true` 不能成为强制进入最终答案的理由。只有晋级 Top N 的弱假说才可进入报告，且最多展示 3 条、不足不凑数；展示时同时呈现天然已报道分支、未验证目标分支、主要反对理由和证伪实验。

禁止把多条各自成立的事实拼成一个未经原文直接支持的机制事实。除非已回读 Evidence 直接支持整句机制，否则“底物与辅因子形成特定共价中间体”“第二底物捕获该中间体”“改变终止方式得到目标产物”只能放在机制类比或模型预测中。天然反应、蛋白归属和辅因子依赖逐项引用对应 Assertion/Evidence；不同来源不能被拼接成目标活性的实测证明。

审核四条召回通道是否都被考虑：同底物、同反应中心、同机制、同中间体或辅因子。知识包确实缺少某条通道时允许记录覆盖缺口，但不得把“底物不同”当作排除理由。候选组内顺序来自底物/端点、反应中心、机制事件、中间体/辅因子角色、产物方向与证据距离的综合比较，不能把同底物命中固定为第一名。不同底物但反应中心和机制更吻合的候选可以排在同底物局部线索之前；单酶方向与多酶路线组件不得混成一个总排名。

若六项表达与归属检查全部通过，可提交 `PASS`；任一项存在未披露问题，提交 `REVISE`。限制中必须说明当前只有五张卡、没有联网、私有知识的实际覆盖范围、没有离线序列/结构候选库，以及条件/毒性数据的实际覆盖。使用 context 返回的最新 `context_digest` 调用 `enzyme_entity_critical_report_commit`。首次提交参数使用 `run_id`、`context_digest`、`review_decision`、`checks`、`limitations`、`next_actions`、`user_summary`；`top_summary` 是工具返回字段，不要放入提交参数。若同一阶段已提交 REVISE，只能在上游输入摘要未变化、逐项重新检查并解决全部 fail/unknown 后，使用 `allow_supersede=true`，并以 `resolved_findings` 为每个原问题记录具体解决方式；不能只把结论改成 PASS。若需要修改机制或候选等上游产物，当前实现不支持同 run 覆盖，应启动新 run。若工具提示 `context_digest is stale`，重新调用一次 `enzyme_entity_run_context(stage="critical_report")` 并核对输入；不要用新 digest 掩盖上游变化。工具会确定性生成 JSON 与 Markdown 报告。成功后只返回工具回执中的 `review_decision`、`final_artifacts`、`top_summary` 和 `user_summary`。

最终 `user_summary` 只根据本轮已提交的机制、候选、路线及原始用户请求组织，不新增科学事实；单酶探索方向和多酶路线组件分别编号，家族线索、诊断对照与未匹配能力另列。用户指定的表格列、Top N 和重点优先于默认篇幅；具体酶两组合计最多 N，不足不凑数，默认最多 5。用户要求两类分别成表时，两节都必须使用 Markdown 表格；即使没有 `route_component` 候选，也应把已提交路线中的局部步骤列入独立组件表，明确其只是步骤、不给具体酶名或具体酶排名。局部组件不能因实体关系命中被写成完整反应“第 1 名”。

最终候选表必须只从 `03_candidate_and_routes.json.entity_expanded_candidates` 逐行投影：`candidate_role=primary` 才能进入“单酶探索方向”，`route_component` 才能进入“多酶路线组件”；按各自 `group_rank` 排序。`diagnostic_control`、`family_hint`、`unmatched_capability` 绝不占具体酶排名。不得凭审核 Agent 自己的偏好把对照酶或家族抬成单酶第 1 位，不得把提交为路线组件的酶改称单酶第 1 位；若发现上游角色与路线叙述矛盾，应写入审核问题并请求修订，而不是在 `user_summary` 中私自改角色。

提交前逐行检查表格中的具体酶与上游角色。工具返回 `user_summary role mismatch` 时，只按已有角色与组内顺序修正答案表格，不重新检索、不改上游角色、不返回 `UNVERIFIED`。模型草案和未核实组件必须保留各自证据标注，不能概括成“所有候选都有本体证据”。原始用户问题决定说明重点与篇幅，但不得改写已提交的科学归属。
本阶段沿用 Workflow 上游回执的 `run_id`；阶段结束时返回 `enzyme_entity_critical_report_commit` 的 `result` 对象，前端从其中提取 `user_summary`。

上文要求的来源数量、运行隔离、私有知识可用性与候选库状态属于内部 `limitations` 和审计产物，不得原样复制到默认 `user_summary`。面向科学用户只说明它们对结论的意义，例如“当前本体证据覆盖有限”“尚未验证具体原子对应与反应配平”“尚缺可用于扩展候选的序列与结构证据”，并保留氧化步骤未闭合、条件和毒性证据不足等科学不确定性。默认不罗列内部实体/断言/证据 ID、数据库或软件名、MCP、联网状态、Workspace 可用性、检索实现和诊断计数；用户明确请求技术诊断时才可说明适用实现。

本插件对外是独立的结构化本体插件。公开文字使用“本体实体、关系、断言及其可核验证据”等自身概念，不称 Wiki、知识卡插件或另一酶发现插件，也不把迁移来源写成另一个产品后端。缺失实体或关系只表示当前本体证据未覆盖，不能写成生物学不存在。


当前 Workspace 私有知识参与规则：使用 `enzyme_entity_workspace_query` 按相关实体 ID 或精确名称查询（scope=both），保留公共与私有分组、条件及冲突；需要时用 next_cursor 续页，不能把一页当成全库。若返回 available=false，只使用公共工具并说明私有能力不可用。候选阶段必须先冻结 baseline，再查询私有知识。私有查询返回的 assertion ID 与 evidence_ids 可直接用于现有账本；引用前必须调用 `enzyme_entity_read_evidence`，不得编造 ID。已审核的 kind=hypothesis/analogy/annotation 仍不是已报道事实；opposes 不能充当候选正向支持。私有事实目前仅允许保守的 reported_related 归属，不冒充 reported_exact。查询到私有新蛋白时可结合它自己的已报道断言作为候选依据，目标活性始终未验证。旧公共通路搜索不含私有边，私有线索只能作为带引用的机制/候选支持，不能捏造 reported_path。冲突须在理由和限制中说明，不能只挑有利证据。
最终提交和重试都会复查私有引用；返回撤回/不可访问错误时不能复用旧报告宣布成功。成功返回工具 result 的完整回执，包括 private_assertion_ids，不能删除私有引用字段。
