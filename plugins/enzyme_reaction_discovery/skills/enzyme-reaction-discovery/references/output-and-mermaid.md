# 最终输出与 Mermaid 规则

## 单一事实源

`07_final_report.json` 是最终事实源。它必须由 `enzyme_report_finalize` 从已校验的 01—06 确定性聚合；Markdown、候选表和 `.mmd` 随后从同一 JSON 渲染，禁止模型分别改写或把完整 07 作为工具参数发送。

最终 JSON 包含原始输入、规范化输入、警告与假设、五类证据账本、Top 3 辅因子、具体酶、机制、路线、候选表、Mermaid、轻量验证建议、限制和下一步。机制与路线使用运行时 `result_limits` 作为上限：未指定时上限各 5 条，用户明确指定时最高 10 条。知识不足时允许少于上限或为空，降低置信度并保留缺口，不能复制内容凑数。聊天摘要保留最终表中的机制、路线及顺序，不再二次截断。

第四阶段内部回执保留运行 ID、PASS/REVISE、最终产物名、Top 摘要与 `user_summary`。主会话和最终报告面板只展示 `user_summary`，默认是简洁中文候选结论，不显示回执 JSON、运行 ID、产物路径或中间证据账本。仅当用户明确要求 JSON 时，按指定字段和格式输出；后续按需导出复用已保存产物，不重跑 Workflow。

## Mermaid

- 使用 `flowchart LR` 等流程图；不伪装成精确结构式。
- 节点 ID 使用英文字母数字和下划线；SMILES 只放在引号标签中。
- 边标签写催化能力、辅因子和候选家族。
- 直接、工程化单酶和多酶路线用不同 subgraph。
- 假设中间体用虚线，硬冲突或未闭合步骤连到警告节点。
- 禁止 `click`、外链、脚本和初始化指令。

## 实验建议边界

只提出区分候选的概念性建议，例如辅因子有无、单酶/组合酶、失活蛋白或空载体、底物类似物、关键中间体/副产物检测。每项必须写明区分对象、对照和观察信号，并固定 `safety_boundary=conceptual_only_no_operational_parameters`。不输出剂量、培养参数、放大工艺或自动实验步骤。

3.5.0：内部产物保留来源类型与固定 verification_note；最终另列 unmatched_capabilities，不混入具体酶表。聊天、Markdown 和 Mermaid 均须显式区分 Wiki 类比、未核实具体酶和未匹配能力。完整 JSON 是报告数据源，不表示其中的假说都是事实。
