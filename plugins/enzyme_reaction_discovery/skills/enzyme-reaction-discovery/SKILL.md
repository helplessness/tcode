# 酶逆向发现

用户输入目标，Wiki 提供既往知识，模型提出并比较新假说。不要将目标论文、新反应答案、测试标签、历史运行结果作为推断资料；模型记忆中的酶活性也不能冒充已检索事实。

## 主管启动边界

本文已包含主管启动所需的全部协议。主管加载本 Skill 后，直接按下文把用户输入传给 workflow_run，不需要先分析化学，也不需要 read 任何补充文件。当前工具列表没有的工具不得调用；read、shell、网页及 MCP 不可用不是启动阻塞。具体机制与证据读取由四个阶段 Agent 使用各自的插件工具完成。

## 四阶段执行

1. 反应定义：保存原始输入，区分文本可见变化、推断与未知；原子对应关系只是未验证假设，记录明显物料/电荷缺口。
2. 机制与辅因子：按需检索本地 Wiki 并读取选定反应证据，先比较少量可达隐藏状态，再平行评估适用的共价与非共价策略；机制数量读取运行时 `result_limits.mechanisms`，默认 5，用户明确指定时可到 10。机制逐条暂存，最终提交不重复发送完整机制数组。解释关键成断键、释放和再生，不用“重排”替代缺失步骤。
3. 家族与路线：先在不看到 Wiki 卡和检索结果的情况下，仅按目标反应与模型知识冻结 3—8 个候选草案；该草案是防锚定基线，不是封闭候选池。复杂端点先保留化学身份假说，天然通路要区分直接步骤与相邻步骤，能回忆时同时提出常规可检索的命名酶和宽家族，描述性占位名不能冒充 named_enzyme。再按需检索 Wiki 核验支持与冲突；新读到且能解释关键事件、不同中间体拓扑或天然终止分支的酶，可以作为检索发现候选加入统一比较。路线数量以运行时 `result_limits.routes` 为上限，默认上限 5 条，用户明确指定时最高 10 条；证据不足允许少于上限或为空，弱路线降低置信度并保留未匹配能力，不复制内容凑数。Wiki 只改变证据状态，不是候选白名单或排序加分项。直接端点与位点匹配优先于仅共享辅因子；局部支持不证明完整路线，未报道不等于不能催化，不凭同底物断言易进化。
4. 轻量批判与报告：仅依据紧凑包检查过度外推与明显矛盾，工具聚合同源报告。四阶段内不新增语义审核或人工审核，未知可随结果保留；阶段完成后仍由主管执行原有语义验收、证据门槛及必要的用户确认，不直接跳过验收交付。

Workflow 完整键是 enzyme-reaction-discovery.mechanism-guided-enzyme-search。第二阶段按需检索并封存 02/03 实际引用的原文；第三阶段第一次 context 只返回目标反应，Agent 先提交 candidate_draft，随后才继承阶段二证据并查询 Wiki。草案与最终排序一同留痕，草案外的检索发现候选也必须按化学适配度参加同一竞争；Wiki 未命中不能静默排除候选，Wiki 命中也不能自动加分。最终阶段追加一次确定性报告生成。不输出详细思维链，不复制大 JSON。遇到明确可修正的参数错误可修正一次；错误留痕但合法修正调用仍可继续，存储、权限和重复错误停止，不自动循环。合理科学比较可以花时间，工具重试不替代推理。

启动时调用 workflow_run(template_key="enzyme-reaction-discovery.mechanism-guided-enzyme-search", input_payload=...)。宿主按模板的 source=user_request 声明自动绑定原始请求到 natural_language_request，插件第一阶段提取其中显式标注的 SMILES。无需主管重新拼装反应字段；已获得结构化输入时也可传 reactants/products，支持 SMILES 字符串或组件对象。不要改写结构或把端点丢进其它别名字段；缺失、冲突和无效端点由插件校验，不因漏传已提供内容而反复询问。

Agent 没有通用网络权限；推理模型和宿主固定配置的 embedding API 可正常调用，embedding 不能获取网页或历史记忆。检索工具自动融合词面和语义排名，不需要 Agent 另调向量工具。若 retrieval.semantic.status 不是 ready，明确记录覆盖限制，不要求重复调用修复基础设施。运行记录固定知识版本、指纹与向量模型摘要；更新 Wiki 或模型后创建新 run，不混用旧证据。

四阶段完成后，主管先交付候选回复，由宿主运行时执行原有语义验收和证据门槛。必要的用户确认只使用最终回复“综合评分”区域的“确认当前结果 / 要求修改”按钮；不得调用 `question` 询问是否验收、是否满意或是否归档。`question` 只可澄清真正缺失的输入，不能代替结果卡验收。不要在用户点击前宣称验收通过，不把验收理解成写团队记忆或归档授权，也不擅自取消系统验证。

## 输出和阅读

用户默认只看到中文候选摘要、主要理由与不确定性。JSON 是内部产物，用户明确索取时才按需展示。不要把路线组件说成完整反应催化酶。

维护者参考文档为 references/reasoning-and-evidence.md、references/workflow-protocol.md 和 references/output-and-mermaid.md。这些不是主管的执行前置条件；不要为了启动 Workflow 调用文件读取工具。各阶段已经配置独立的提示词和工具契约。

## 开放探索（3.5.0）

允许机制/辅因子 model_hypothesis、具体酶 model_enzyme 和未匹配能力 unmatched_capability。Wiki 仍是唯一外部证据源，模型自身知识只能作为“未经过 Wiki 核实”的假说。库外项没有 Wiki 卡是正常情况，不能编造 card_id、来源或数据库编号。具体酶与尚未匹配的催化能力分开呈现，不自动写回 Wiki。四阶段、工具预算、禁止联网与 R1 主管最终验收保持不变。用户确认只接受当前结果，不会使模型假说成为科学事实。
