# Changelog

## 未发布 — 2026-10-10：能力复用、候选去重与 Wiki 去锚定

- 机制分析、筛选和最终审核均检查同一催化动作在不同中间体上的复用可能性，同时区分单蛋白能力与多个家族成员能力，未知活性不自动等同于必须工程化。
- 筛选提交新增可选 `draft_dispositions`（最多 8 条）；合并必须指向已选候选并解释身份和完整目标范围。遗漏草案标为未评估，由既有科学审核检查，不自动加分或强制保留。
- 移除 3.10.1 的机制锚点自动补候选和固定覆盖分。锚点仅作为待比较证据，Wiki 核实程度与目标化学适配分别判断。
- 同步解耦包；不修改知识卡，不增加模型阶段、检索轮次或输出候选数，不预置特定文献答案。

## 3.10.4 — 2026-10-04：公开提交契约与运行时校验统一

- `enzyme_screen_commit` 的公开 Tool Schema 现在直接复用运行时用于逐项校验的严格候选 Schema；非法身份组合会在工具调用边界立即拒绝，不再进入一次必然失败的提交。公开角色枚举复用现有归一化映射，因此历史别名仍可进入 handler 并转换为三个标准角色。路线继续在 handler 内先兼容既有别名、再使用严格 Schema 逐项校验。
- 同步当前知识版本、卡片数、工具数及 Plugin SDK readiness 快照；不改变候选生成、科学评分、Wiki 内容或证据边界。

## 3.10.3 — 2026-10-02：探索角色枚举归一与提示词枚举约束

- 修复“模型把提示词里的描述性说法当成 `candidate_role` 枚举（现场：`exploratory_candidate`），导致候选被整条拒绝，并连带使引用它的路线报 `route step must reference a selected candidate`”的问题：`exploratory_candidate`、`exploratory`、`exploration`、`exploratory_route_component`、`exploratory_component`、`exploratory_diagnostic_control` 及中文“探索候选/探索方向候选”现在归一到合法角色（默认 `primary`）；只承担局部步骤的情况仍由 mechanism/component_function 规则在构建阶段重新分层。无法识别的取值仍照常校验失败，不做静默改写。
- 在阶段三提示词中显式约束 `candidate_role` 只能取 `primary`、`route_component`、`diagnostic_control`，禁止自造词。
- 新增回归测试：`exploratory_candidate` 等自造角色枚举被归一为合法角色并记录审计说明。

## 3.10.2 — 2026-09-30：REVISE 正常结束与产物校验按结论生效

- 修复“第四阶段审核结论为 `REVISE` 时，产物校验仍强制要求 `07_final_report.*` 与 `mechanism_routes.mmd`，导致一次正确的修订判定被误报为 `missing_artifact / artifact_file_missing` 并阻塞”的问题：`required_artifacts` 与 `files_exist` 现在按 `review_decision` 生效，`PASS` 校验全部四个产物，`REVISE` 只校验 `06_critique.json`。

- 主聊天不再直出内部校验码：`stage output rejected: missing_artifact, artifact_file_missing` 这类内部摘要会被翻译成用户可读的中文说明，原始技术细节仍在运行详情中查看。

## 3.10.1 — 2026-09-30：锚点卡覆盖兜底与枚举归一

- 修复“模型只记录机制锚点卡覆盖缺口、不提交候选”导致锚点酶被静默漏掉的问题：阶段三提交后，对每个未被比较、且本轮已有可引用已读片段（claim）的机制锚点卡，确定性补入一条低置信度 `wiki_enzyme` 候选（固定覆盖分、`confidence=low`、`mechanism_ids` 来自锚点机制），并逐条记录“未被模型逐一比较”的知识缺口。天然反应含目标反应物时标 `reported_exact` 并回填逐字短引，否则标 `unresolved` 且空引文。没有已读片段的锚点卡仍按原样记录覆盖限制，不补造证据。
- 修复“可修正的枚举同义拼写让整条候选/路线被丢弃”的问题：提交前把 `candidate_role`（`main_candidate`→`primary` 等）、`confidence`（`unknown`→`unresolved` 等）、`component_function`、`substrate_relation`、`route_type` 的同义词归一到 schema 枚举，并把 `evidence_uncertainty`、`target_activity_status` 这类非 schema 回显字段移入该项的知识缺口/未闭合项，而不是整项拒绝。无法识别的取值仍照常校验失败，不做静默改写。
- 候选/路线 schema 的 `mechanism_ids` 只接受 `M1`–`M10`：锚点机制 id 不合法时不再把合法候选带成非法项，只省略该关联。
- 新增回归测试：锚点卡漏比较 + `main_candidate`/`unknown` 同义枚举下，CEAS（ERD-CARD-001）仍以低置信度主候选进入 `04_candidates.json`。

## 3.10.0 — 2026-09-30：防锚定基线与检索发现候选

- 机制阶段要求比较适用的直接催化、共价／辅因子中间体与替代终止、多酶分解等通用拓扑，避免把一种净变化拆解当成唯一解释；不含特定酶、辅因子或测试反应答案。
