# 安全、权限与信任

## 1. 三个概念不要混淆

1. **Manifest 申请**：插件声明希望使用什么能力。
2. **Host 授权**：管理员在运行配置中允许申请范围的全部或子集。
3. **执行模式**：Host 根据官方身份和精确信任策略选择主进程或隔离 Worker。

Manifest、包签名、社区审核和安装记录都不能单独授予运行时权限。

## 2. 执行模式

### controlled-host

适用于：

- 仓库内精确官方插件路径；
- 运维在 `TCODE_PLUGIN_TRUSTED_ALLOWLIST` 中按完整名称精确授权的插件。

它仍要经过 Manifest、配置、权限、Policy、Approval、Sandbox 和加载事务校验。“受信”不表示没有安全检查。

### isolated-worker

未知社区插件的默认模式：

- 生产环境一个插件一个 Docker 容器；
- Host 不导入插件入口代码；
- 不继承 Host Secret 环境；
- Worker 容器固定为无网络、只读、非 root，不挂载 Docker Socket；
- 禁止直接工作区、Prompt、Event、Command、Skill、Agent 和 MCP Server Contribution；
- 只允许贡献 Tool；网络、命令、Host Tool、MCP Tool 和现有 Skill 必须经 Host Broker 委派；
- 有 CPU、内存、文件、进程、请求时间和协议大小上限；
- Worker 崩溃或超时只影响本插件，卸载会精确删除容器并撤销该实例全部贡献。

生产设置 `TCODE_PLUGIN_ISOLATION_BACKEND=container` 后，只接受 Sandbox Runner 管理的 Docker 容器且不回退。本地开发或测试可以显式选择 `native`，此时 macOS 使用 `sandbox-exec`、Linux 使用 `bwrap`；Native Worker 仍不能绕过 Broker 启动 Host 工具沙盒。

### quarantined

隔离或撤销中的包不可运行。管理员需要先解决审核、安全或供应链问题。

## 3. 权限 Scope

Manifest 支持以下权限申请：

| Scope | `patterns` 示例 | 保护对象 |
| --- | --- | --- |
| `filesystem.read` | `./data`, `./data/**` | 读取文件和列目录 |
| `filesystem.write` | `./output`, `./output/**` | 创建目录和写完整文件 |
| `process.exec` | `git`, `python3` | 无 shell 子进程命令 |
| `env.read` | `MY_PLUGIN_*` | 指定环境变量名称 |
| `network.outbound` | `api.example.com:443` | 出站目标声明 |
| `tools.invoke` | `paper_search`, `mcp_biology_lookup` | 调用现有 Host/MCP Tool |
| `skills.invoke` | `document.pdf` | 限制 `skill_run` 的具体 Skill |
| `sandbox.profile` | `executor` | 允许进程请求指定 Sandbox Profile |
| `memory.read` | `session:*`, `team:team-1` | 召回记忆及订阅记忆生命周期快照 |
| `memory.write` | `session:*` | 写入指定语义 Scope |
| `memory.delete` | `session:*` | 删除单条记忆 |
| `memory.promote` | `session:*`, `team:*` | 在已授权 Scope 之间提升记忆 |
| `memory.maintenance` | `session:session-1` | 清空完整记忆 Scope |

未知隔离插件不接受 `filesystem.*`、`env.read` 和 `memory.*` 直接授权；它应通过获准的 Host Tool、MCP Tool 或 Skill 交换内容。`network.outbound`、`process.exec`、`tools.invoke`、`skills.invoke` 和 `sandbox.profile` 也只在 Host 再次授权后由 Broker 生效。首版 `ctx.memory` 只向官方或被精确信任的 `controlled-host` 插件开放。

示例：

```json
{
  "permissions": [
    {
      "scope": "filesystem.read",
      "patterns": ["./data", "./data/**"],
      "description": "读取插件输入数据。",
      "required": true
    },
    {
      "scope": "filesystem.write",
      "patterns": ["./output", "./output/**"],
      "description": "写入插件生成结果。",
      "required": false
    }
  ]
}
```

`required: true` 的权限如果被管理员完全拒绝，插件加载失败；`required: false` 可以被收窄为空，插件必须处理能力不可用的情况。

## 4. Host 如何收窄权限

管理员可以在 `plugins.json` 中把申请范围缩小或关闭：

```json
{
  "name": "trusted-report-plugin",
  "path": "./plugins/trusted_report_plugin",
  "enabled": true,
  "permissions": {
    "filesystem.read": ["./approved-input/**"],
    "filesystem.write": false
  }
}
```

Host 授权不能超过 Manifest 申请；新增 Scope 或扩大 pattern 都会失败关闭。`required` 属性归 Manifest 所有，运行配置不能偷偷改变。

## 5. 副作用级别与权限

| `side_effect_level` | 典型行为 | Host 要求 |
| --- | --- | --- |
| `none` | 纯计算、格式转换 | 不需要文件或进程权限 |
| `read` | 网络读取或受控读取 | 需要相应读能力授权 |
| `write` | 写文件、修改状态 | 需要相应 `filesystem.write` 授权，可能触发审批 |
| `process` | 启动命令、调用 Host Tool 或 Skill | 需要对应 Scope，并继续受 Host Policy、Approval 和 Sandbox 约束 |

工具不能把真实副作用声明成 `none` 来绕过隔离。`network.request` 至少要求 `read`；`process.run` 和 `tools.invoke` 至少要求 `process`。Worker 中直接访问网络、宿主文件、Docker 或子进程仍会被容器隔离层拒绝。

## 6. 信任名单

```bash
TCODE_PLUGIN_TRUSTED_ALLOWLIST=plugin-a,plugin-b
```

约束：

- 只接受精确插件名称；
- 不支持通配符；
- 不应把整个社区或命名空间加入名单；
- 官方仓库路径不需要重复加入；
- 修改名单属于运维安全决定，应经过代码、供应链和权限审核。

社区注册表中的 `verified` 只表示签名和人工审核通过，不会自动写入该环境变量。

## 7. 插件开发安全检查表

- 模块导入阶段没有网络、文件写入、线程或进程副作用；
- 不导入私有 `tcode_agent.*` 模块；
- 不记录 Token、Cookie、密码、完整配置或用户正文；
- 不在 `ToolOutput.metadata` 放敏感对象；
- 受控宿主插件的路径都通过 `ctx.workspace`；未知插件通过授权 Tool/Skill 交换内容；
- 所有命令都通过 `ctx.process.run`，不使用 `shell=True`；
- 工具副作用级别与实际行为一致；
- 输出有长度上限，异常不包含 Secret；
- `stop` 能在重复卸载和部分启动后安全执行；
- 不把 `requestedTrust: trusted` 当成权限授权。

更完整的容器参数、依赖安装、Tool/MCP/Skill 调用和生产部署说明见[容器隔离与受控能力调用](./07-容器隔离与受控能力调用.md)。
