# 测试、打包、发布与安装

## 1. 开发期检查

```bash
python scripts/plugin.py validate ./my-plugin
python scripts/plugin.py test ./my-plugin
python scripts/plugin.py doctor ./my-plugin
```

建议把三条命令加入 CI。

### validate

静态检查：

- Manifest v2 必填字段和未知字段；
- API、SDK、Python 版本范围；
- 包内路径、入口和配置 Schema；
- 权限、依赖和 Contribution 声明。

该命令不导入插件入口代码。

### test

在 `validate` 之外检查：

- 入口 Python 语法；
- 是否导入 `tcode_agent.plugin_sdk` 以外的私有运行时模块。

### doctor

输出机器可读、脱敏 JSON，适合发布审核和排障。`status` 不是 `pass` 时不要打包发布。

## 2. 插件自己的合同测试

至少验证：

- `PluginMetadata` 与 Manifest 一致；
- 工具名称、Schema、副作用级别和结果预算固定；
- 正常输入和边界输入；
- 健康检查不泄露敏感信息；
- `stop` 可重复执行；
- 失败不会留下后台任务或外部资源。

最小测试示例：

```python
import unittest

from plugin import Plugin


class PluginContractTests(unittest.IsolatedAsyncioTestCase):
    """验证插件公开身份和纯业务处理逻辑。"""

    def test_metadata_matches_manifest(self) -> None:
        """要求代码身份与 plugin.json 保持一致。"""

        self.assertEqual("community-echo", Plugin.info.name)
        self.assertEqual("0.1.0", Plugin.info.version)


if __name__ == "__main__":
    unittest.main()
```

## 3. 可复现打包

```bash
python scripts/plugin.py pack ./my-plugin \
  --output ./dist/my-plugin-0.1.0.tcode-plugin
```

打包器会：

- 固定文件顺序、时间戳和权限；
- 排除 `.git`、缓存、`build`、`dist`、`__pycache__` 和 `.pyc`；
- 生成包内文件清单；
- 返回 SHA-256 和大小；
- 拒绝路径逃逸、重复路径和符号链接包。

发布前用干净工作区连续打包两次，SHA-256 应相同。

## 4. 生成签名密钥

```bash
python scripts/plugin.py keygen \
  --private-key ./keys/publisher.pem \
  --public-key ./keys/publisher.pub.pem
```

私钥权限会设置为仅当前用户可读。不要提交私钥、复制到插件包或写入 CI 日志；生产发布应从密钥管理系统临时注入。

## 5. 发布到自有注册表

```bash
python scripts/plugin.py publish ./dist/my-plugin-0.1.0.tcode-plugin \
  --registry ./.tcode/community/registry.json \
  --signer example-publisher \
  --signing-key ./keys/publisher.pem
```

发布记录包含：

- 名称和不可变版本；
- SDK/Python 范围；
- 包路径、大小和 SHA-256；
- Ed25519 签名、公钥和指纹；
- 权限申请；
- 发布时间、审核状态和审计记录。

`publish` 不会安装、启用或授权插件。同一名称和版本不能被覆盖，应提升版本后重新发布。

## 6. 审核状态

| 状态 | 含义 | 可安装 |
| --- | --- | --- |
| `community` | 已提交，尚未形成高级审核结论 | 可以，但保持隔离候选且默认禁用 |
| `verified` | 有效签名且明确审核人通过 | 可以，仍不自动授予宿主信任 |
| `official` | 官方发布结论 | 可以，运行身份仍由 Host 路径和策略决定 |
| `quarantined` | 正在调查或不满足运行边界 | 不可以 |
| `revoked` | 已撤销版本 | 不可以 |

审核命令：

```bash
python scripts/plugin.py review my-plugin 0.1.0 \
  --status verified \
  --reviewer reviewer-name \
  --note "合同测试、依赖和权限审核通过" \
  --registry ./.tcode/community/registry.json
```

`official` 和 `verified` 必须有有效签名和非空审核人。

## 7. 安装

### 桌面直接导入（无需手动登记）

桌面端“扩展 → 插件 → 安装插件”：在独立弹窗选择 `.tcode-plugin` 包后点击“安装插件包”，宿主完成静态校验并安装到当前工作区 `.tcode/installed-plugins/<name>/`，自动登记为禁用。点击“加载已安装插件”后才运行隔离插件；异步目标还需填地址、检查连接并批准输入发送。安装弹窗独立滚动，不占用插件列表高度；返回列表后仍可加载、卸载或删除。工具、命令、钩子和诊断移入“高级信息”，不是普通安装的必填步骤。远程配置请参考 [MCP 接入指南](../../tcode_agent/MCP_QUICKSTART.md)。

直接导入不验证发布者签名，只校验包结构、清单和原包摘要，不授予可信宿主身份。同名插件不覆盖。上传上限 32 MiB、解压上限 128 MiB、最多 2000 条目。需签名渠道时继续使用下述 SDK 注册表安装。

“卸载”仅停止运行并禁用，保留安装文件；“删除插件”仅向当前工作区导入的包开放，需先卸载并确认，随后删除安装目录、插件登记及已停用的异步连接配置。不会删除已有任务记录或任务结果，不会取消远端计算。可用插件列表中操作，无需手改 `plugins.json`；内置插件和外部源码目录不能在此删除。删除后可重新导入，但须重新配置和授权异步目标。

### SDK 注册表安装

```bash
python scripts/plugin.py install my-plugin 0.1.0 \
  --registry ./.tcode/community/registry.json \
  --plugin-home ./.tcode/plugins
```

安装过程会再次验证版本、摘要、签名元数据和包路径，然后解包到精确插件目录。安装成功后状态为 `installed-disabled`，不会自动加载代码。

管理员完成权限与执行模式审核后，再在 `plugins.json` 或受认证的插件管理界面显式启用。

## 8. 卸载

先通过运行时卸载插件实例，再删除安装包：

```bash
python scripts/plugin.py uninstall my-plugin \
  --registry ./.tcode/community/registry.json \
  --plugin-home ./.tcode/plugins
```

CLI 只删除注册表精确记录、且位于指定 `plugin-home` 内并与插件名称匹配的目录。路径缺失或被替换为普通文件时会失败关闭，不会静默删除注册记录。

## 9. 推荐 CI 顺序

```bash
python scripts/plugin.py validate ./my-plugin
python scripts/plugin.py test ./my-plugin
python scripts/plugin.py doctor ./my-plugin
python -m unittest discover -s ./my-plugin -p "test_*.py"
python scripts/plugin.py pack ./my-plugin --output ./dist/my-plugin.tcode-plugin
```

CI 应保存 Doctor JSON、测试报告、包 SHA-256 和签名身份，但不能保存私钥或真实 Secret。
