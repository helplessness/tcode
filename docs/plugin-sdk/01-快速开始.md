# 快速开始

本章创建一个默认隔离、无外部副作用的回显插件。它是社区插件最安全的起点。

## 1. 环境准备

确认当前 Python 为 3.11 或更高版本，并能导入 TCode：

```bash
python --version
python -c "import tcode_agent.plugin_sdk as sdk; print(sdk.PLUGIN_SDK_VERSION)"
```

当前 SDK 版本应输出 `1.4.0`。

## 2. 创建插件项目

在 TCode 仓库根目录执行：

```bash
python scripts/plugin.py create community-echo --path ./tmp/community-echo
cd ./tmp/community-echo
```

生成结构：

```text
community-echo/
├── README.md
├── config.schema.json
├── plugin.json
├── plugin.py
└── test_contract.py
```

其中：

- `plugin.json`：Manifest v2，声明身份、版本、依赖、权限和贡献；
- `config.schema.json`：插件配置的 JSON Schema；
- `plugin.py`：插件入口和生命周期；
- `test_contract.py`：最小 SDK 合同测试。

## 3. 理解入口代码

模板的核心结构如下：

```python
from __future__ import annotations

from collections.abc import Mapping
from typing import Any

from tcode_agent.plugin_sdk import (
    PluginContext,
    PluginHealth,
    PluginHealthStatus,
    PluginMetadata,
    ToolCallContext,
    ToolDefinition,
    ToolOutput,
)


class Plugin:
    """提供一个没有外部副作用的回显工具。"""

    info = PluginMetadata(
        name="community-echo",
        version="0.1.0",
        description="社区回显示例插件。",
        plugin_type=("tool",),
    )

    def __init__(self) -> None:
        """初始化默认前缀和未绑定的插件 Context。"""

        self._context: PluginContext | None = None
        self._prefix = "community-echo"

    async def start(
        self,
        ctx: PluginContext,
        config: Mapping[str, Any],
    ) -> None:
        """读取已校验配置并注册回显工具。"""

        self._context = ctx
        self._prefix = str(config.get("prefix") or self._prefix)
        ctx.tools.register(
            ToolDefinition(
                name="community_echo",
                description="返回带插件前缀的文本。",
                input_schema={
                    "type": "object",
                    "properties": {"text": {"type": "string"}},
                    "required": ["text"],
                    "additionalProperties": False,
                },
                handler=self._echo,
                side_effect_level="none",
            )
        )

    async def _echo(
        self,
        arguments: Mapping[str, Any],
        _call: ToolCallContext,
    ) -> ToolOutput:
        """返回已经通过 Schema 校验的输入文本。"""

        text = str(arguments.get("text") or "")
        return ToolOutput(
            title="Community Echo",
            content=f"{self._prefix}: {text}",
        )

    async def health(self) -> PluginHealth:
        """报告插件是否已经完成启动。"""

        if self._context is None:
            return PluginHealth(PluginHealthStatus.UNHEALTHY, "插件尚未启动")
        return PluginHealth(PluginHealthStatus.HEALTHY, "插件已就绪")

    async def stop(self, _reason: str = "unload") -> None:
        """卸载时释放对公开 Context 的引用。"""

        self._context = None
```

注意：`input_schema` 是实际运行时参数验证来源。不要只在处理器中自行检查输入，也不要依赖 Schema 默认值被自动写回参数。

## 4. 本地校验

回到仓库根目录，依次执行：

```bash
python scripts/plugin.py validate ./tmp/community-echo
python scripts/plugin.py test ./tmp/community-echo
python scripts/plugin.py doctor ./tmp/community-echo
```

三条命令都应返回 JSON，且 `status` 为 `pass`。

- `validate` 不执行插件代码，只校验 Manifest、Schema 和路径；
- `test` 增加 Python 语法及私有运行时导入检查；
- `doctor` 输出适合 CI 和人工审核的脱敏诊断。

## 5. 打包

```bash
mkdir -p ./tmp/dist
python scripts/plugin.py pack ./tmp/community-echo \
  --output ./tmp/dist/community-echo-0.1.0.tcode-plugin
```

输出包含包路径、文件清单、大小和 SHA-256。相同源码重复打包应得到相同摘要。

## 6. 加入本地插件配置

安装或复制到受管插件目录后，由运维或管理员在 `plugins.json` 中显式登记。当前仓库本地 Runner 允许 `plugins/` 根，开发 Fixture 建议放在 `plugins/third_party_fixtures/` 下：

```json
{
  "auto_discover": false,
  "plugins": [
    {
      "name": "community-echo",
      "path": "./plugins/third_party_fixtures/community-echo",
      "enabled": false,
      "config": {
        "prefix": "Echo"
      },
      "source": "plugins.json"
    }
  ]
}
```

复制目录和装载是两件事。当 `auto_discover` 为 `false` 时，只复制目录不会导入代码；还必须在 `plugins.json` 登记，然后通过插件页、`/api/plugins/load` 或 `reload-config` 显式启用。

不需要手写 Docker `-v`。Sandbox Runner 会在加载时验证插件路径是否位于 `TCODE_PLUGIN_RUNNER_ALLOWED_PLUGIN_ROOTS`，然后把该目录以只读方式挂载到 Worker。如果你准备使用 `./.tcode/plugins`、`/srv/community-plugins` 或其他安装根，必须先由运维把该精确根目录加入 Runner 白名单并重启 Runner。

未知社区插件不会因 `enabled: true` 进入主进程。它会进入独立隔离 Worker；任何网络、命令、Host Tool 或 Skill 能力都必须同时经过 Manifest 申请、管理员授权和 Host Broker。生产容器后端不可用时会失败关闭。

## 7. 下一步

- 需要更多工具：继续调用 `ctx.tools.register(...)`，并保证工具名全局唯一。
- 需要配置：修改 `config.schema.json`，再从 `config` 映射读取。
- 需要 Prompt 或 Event：先阅读 [SDK API 与生命周期](./03-SDK-API与生命周期.md) 和 [安全、权限与信任](./04-安全权限与信任.md)。
- 需要发布给其他开发者：阅读 [测试、打包、发布与安装](./05-测试打包发布与安装.md)。
- 需要调用网络、MCP Tool 或 Skill：阅读 [容器隔离与受控能力调用](./07-容器隔离与受控能力调用.md)。
- 需要让插件携带多阶段流程：阅读 [插件声明式 Workflow](./08-插件声明式Workflow.md)。
