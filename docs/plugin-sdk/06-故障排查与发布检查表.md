# 故障排查与发布检查表

## 1. 先运行 Doctor

```bash
python scripts/plugin.py doctor ./my-plugin
```

Doctor 输出只包含稳定诊断、路径和 SDK 版本，不包含插件配置值或 Secret。优先根据 `code` 处理，而不是只看异常文本。

## 2. 常见问题

### Manifest 无法通过

检查：

- 是否同时存在 `plugin.json`、入口文件和配置 Schema；
- `apiVersion` 是否为 `1.0`；
- `sdk` 是否包含 `1.2.0`；
- `python` 是否包含 Host 的实际 Python 版本；
- 是否有拼写错误或未知字段；
- 所有路径是否为包内相对路径。

### `PluginMetadata` 不匹配

`PluginMetadata.name` 和 `version` 必须与 Manifest 完全相同。发布新版本时要同时修改两个位置。

### 私有运行时导入被拒绝

错误示例：

```python
from tcode_agent.plugins.manager import PluginManager
```

正确做法是只通过：

```python
from tcode_agent.plugin_sdk import PluginContext, ToolDefinition
```

如果公开 SDK 没有需要的能力，不要绕过边界；应提交 SDK 能力提案或把插件保持为官方内部扩展。

### 插件声明 trusted 但仍进入 Worker

这是预期行为。`requestedTrust` 是请求，只有官方精确路径或 `TCODE_PLUGIN_TRUSTED_ALLOWLIST` 中的精确名称才能进入受控宿主。

### verified 插件仍未获得文件或进程权限

这是预期行为。签名与审核不授予运行时权限。权限必须先在 Manifest 申请，再由 Host 配置在申请范围内明确授权；未知社区 Worker 的命令、网络、Tool 和 Skill 只通过 Broker 生效，直接文件权限仍不开放。

### Worker 无法启动

生产检查：

- `tcode-plugin-runtime:py312` 固定镜像是否已经构建；
- Sandbox Runner 是否可达且 Token 一致；
- 插件包是否位于 `TCODE_PLUGIN_RUNNER_ALLOWED_PLUGIN_ROOTS`；
- 插件文件是否允许非 root 容器 UID 只读访问；
- Runner 是否允许 `plugin_runtime` 和 `plugin_network`；
- 插件是否只声明 `contributes: ["tools"]`；
- Manifest 必需权限是否由管理员显式授权；
- 插件模块是否在导入时直接访问网络、文件或私有运行时。

设置 `TCODE_PLUGIN_ISOLATION_BACKEND=container` 时，容器后端缺失会失败关闭，不会自动降级。本地显式 `native` 模式才检查 macOS `sandbox-exec` 或 Linux `bwrap`。

### 工具参数验证失败

检查 `input_schema`：

- 根是否为 `type: object`；
- 必填参数是否进入 `required`；
- 是否建议使用 `additionalProperties: false`；
- Handler 是否错误地假设 Schema 默认值已经写回；
- 实际参数类型是否与 Schema 一致。

### 工具注册冲突

工具名是全局 ID。使用插件前缀，例如 `acme_report_generate`，避免 `read`、`search`、`run` 这类通用名称。

### Workflow 无法加载

检查：

- Manifest 是否用 `workflows` 声明了真实存在的包内文件或目录；
- 每个目录是否包含 `workflow.json`，Prompt 是否位于同一模板目录内；
- 本地 `template_key` 是否只使用小写字母、数字、`_`、`-`；
- 每个阶段是否显式声明 `depends_on`，且依赖图无环；
- `call_type` 是否仅为 `agent` 或 `subagent`；
- `metadata.routing.auto_start` 是否为 `false`；
- 最终调用是否使用宿主生成的 `<plugin-name>.<template-key>` 完整名称。

### 加载后立即变成不健康

检查 `health()`：

- 启动完成前不要返回 `HEALTHY`；
- 临时依赖不可用可以返回 `DEGRADED`；
- 无法安全工作时返回 `UNHEALTHY`，Host 会拒绝发布本次贡献；
- `details` 必须可序列化且不含敏感信息。

### 卸载后仍有后台活动

Context 注册的贡献由 Host 精确回收，但插件自行创建的 `asyncio.Task`、客户端或文件句柄必须由插件保存并在 `stop()` 中关闭。不要创建无法追踪的裸后台线程。

## 3. 发布前开发者检查表

- [ ] 插件只导入 `tcode_agent.plugin_sdk` 公共 API；
- [ ] Manifest 和 Metadata 名称、版本完全一致；
- [ ] Manifest 没有未知字段或包外路径；
- [ ] 配置 Schema 拒绝未知字段且不包含 Secret 默认值；
- [ ] 每个工具都有稳定名称、明确描述、严格 Schema 和正确副作用级别；
- [ ] 每个 Workflow 都有无环依赖、最小 Tool 白名单、存在的 Prompt 和 `auto_start: false`；
- [ ] 所有函数和类都有清晰中文注释；
- [ ] 输出和健康诊断不包含 Token、用户正文或敏感路径；
- [ ] `validate`、`test`、`doctor` 全部通过；
- [ ] 插件自己的正常、边界、失败和卸载测试通过；
- [ ] 相同源码重复打包得到相同 SHA-256；
- [ ] 私钥没有进入仓库、包、日志或测试 Fixture；
- [ ] 版本、变更说明、权限原因和兼容范围已更新。

## 4. 审核人检查表

- [ ] 包摘要与发布记录一致；
- [ ] Ed25519 签名和公钥指纹有效；
- [ ] 依赖来源、许可证和供应链风险已检查；
- [ ] 权限申请是完成职责所需的最小集合；
- [ ] 模块导入阶段没有副作用；
- [ ] 工具副作用声明与代码行为一致；
- [ ] 网络、文件、进程和环境变量访问没有绕过 Context；
- [ ] 错误、日志、Metadata 和 Doctor 输出完成脱敏；
- [ ] 隔离 Worker 或受控宿主模式选择有明确依据；
- [ ] 安装后保持禁用，等待管理员显式启用。

## 5. 版本与兼容政策

- SDK `1.x` 遵循语义化版本；
- 新增可选能力可以进入 minor 版本；
- 破坏公开签名只能进入下一个 major；
- 普通弃用至少保留两个稳定 minor 或 90 天，以较长者为准；
- 高危安全问题可以立即失败关闭，但必须给出安全说明和可识别诊断；
- 插件应声明真实兼容范围，不要无依据写无限上界。
