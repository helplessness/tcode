# TCode Desktop：macOS 开发版

当前交付包含可运行的桌面宿主、桌面专用布局和部分原生文件/通知交互。任务协作、工作流、定时任务、文献 Wiki、本体知识和插件复用现有业务组件；这不等于这些功能的远程服务已在本机全部配置完成。

## 安装包准备状态

macOS arm64 独立 Python 后端和未签名 DMG 已经可以构建，不依赖用户安装 Python、Node.js 或运行时 `PYTHONPATH`。当前 DMG 适合本机开发验收；对外分发仍需 Apple Developer ID 签名和公证。

后端产物位于 `build/release/backend/`，DMG 位于 `desktop/release/`。当前完整流程、配置与发布边界见 [macOS 打包指南](../docs/gui/12-macos-dmg-packaging.md)。本页历史验证记录不是当前源码重打包证明。

## 打开方式

从干净副本首次登录、添加并测试模型、发送第一条消息，请按[根 README 的 macOS 快速开始](../README.md#macos启动桌面端)操作。设置好首次登录密码后，从项目根目录运行：

```bash
./scripts/init_local_config.sh  # 首次运行：一次补齐配置；已安装 Web 可跳过
./scripts/start_desktop.sh
```

也可以在 Finder 中双击本目录下的 **启动 TCode.command**。这是开发启动器，会打开终端并启动独立桌面窗口，目前不是已签名的安装包。

首次启动需要联网，安装桌面依赖、创建 `.desktop-venv`、构建现有前端。需要本机已有 Node.js 22.12+/npm 和 Python 3.12+。后续前端源码未变化时复用构建。已有可用环境也可以显式指定：

```bash
TCODE_DESKTOP_PYTHON=/absolute/path/to/python ./scripts/start_desktop.sh
```

启动优先使用 `.tcode-local/desktop.env`；可用 `TCODE_DESKTOP_ENV_FILE` 指定其他文件。保留对 `TCODE_ENV_FILE` 的显式开发配置兼容。没有桌面环境文件时复用现有模型/登录配置，但 MCP 路由始终使用独立桌面文件，不继承 Web 的本机 MCP 或 Runner。缺基础配置时按[配置指南](../docs/CONFIGURATION.md)初始化。

### 电脑控制与隐私

电脑控制每次启动默认关闭。关闭时，查看状态、重新检查权限或清理任务都不会启动 Cua 驱动，因此不会从该实例发送驱动遥测。只有显式打开窗口内的「允许 Computer Use」才会启动驱动；关掉会撤销授权并停止驱动。启用时 Cua 默认可能发送产品遥测，可按 [Cua 驱动版本说明](https://github.com/trycua/cua/releases/tag/cua-driver-rs-v0.35.2)确认版本，并用驱动自身的 `telemetry status` / `telemetry disable` 查询或关闭。启用开关不替代 macOS 系统权限或任务授权。

追加指导统一使用持久化队列，不再读取 `TCODE_STEER_V2_ENABLED`。原生 Harness 的「追加」接入当前轮；「排队」仍明确启动下一轮。已有旧队列在读取时迁移。

### 独立测试实例

已有桌面依赖、Python 环境和前端构建后，在项目根目录运行：

```bash
npm --prefix desktop run dev:test
```

窗口标题带“独立测试”，可以与正式实例同时运行。每次启动新建系统临时目录 `tcode-isolated-*`，终端会打印准确路径；数据库、工作区、Cookie、浏览器缓存、HOME/XDG 目录、日志和服务配置均独立，不复制现有数据，也不加载开发环境的服务或模型配置。

登录只读取 `.tcode-local/symphony_route.env` 的 `TCODE_BOOTSTRAP_EMAIL`、`TCODE_BOOTSTRAP_PASSWORD`、`TCODE_BOOTSTRAP_USER_ID`。支持该字段自己的 `${字段:-默认值}` 表达式，不执行配置文件中的 shell 命令，不另存明文密码。可通过 `TCODE_DESKTOP_TEST_LOGIN_CONFIG=/绝对路径/账号.env` 指定其他登录文件。全新的认证数据库使用这些初始账号信息，不会修改正式账号密码。

测试数据保留在打印的临时目录中，退出后不会写回正式实例；下一次测试默认重新创建空目录。测试实例不继承远程服务地址或密钥，只启动自己的本地后端与 Job Protocol。

### 远程服务配置（正式实例）

客户端不启动 Sandbox Runner，也不要求 Docker。公开桌面包包含 TCode 自带的通用 Job Protocol，不打包私有 TMCP；实际计算服务和计算沙箱仍可部署在远端。

- `.tcode-local/desktop-mcp.json`：已有外部 Job Protocol 地址则复用。没有外部地址时，启用通用异步 MCP 后重启，或设置 `TCODE_MANAGED_JOB_PROTOCOL=1`，即自动启动本机网关。无异步配置不启动。旧 TMCP 任务继续依赖原服务；不自动迁移或重投。可用 `TCODE_DESKTOP_MCP_CONFIG` 指定其他文件。
- `.tcode-local/desktop.env`：配置 `TCODE_DESKTOP_ARTIFACT_SERVICE_URL` 为远程文件服务地址，以及相应的 `TMCP_ARTIFACT_API_TOKEN`。模板为 `config/templates/desktop.env.example`，可继续引用本机 `local.env` 的模型和登录配置。
- 修改后使用应用菜单“重启本地服务”。有未结束远程任务时不要切换服务器。桌面标题栏提供连接状态及重新检查按钮，不显示密钥。
- 缺失或无效配置时仍可打开桌面、浏览本地内容；不启动任务提交 worker，不回退连接 Web 的 localhost 服务。文件服务缺失时明确阻断相关传输。

本地原生隔离现已接入基础文件工具、断网单进程命令、离线技能动作和隔离型插件工具。每次启动运行真实 Seatbelt 正反向自检；失败时阻断执行，不退回宿主或 Docker。插件工具使用只读源码副本和受监督 Worker，宿主导入型插件仍禁用。技能动作不能联网、派生进程或依赖尚未开放的外部挂载。本地 stdio MCP、外部 CLI Harness 和自动 Git worktree 尚未接入，继续禁用。

### 本地执行方式和限制

在工作区导入小文件后，可让 Agent 使用 read/write/edit/glob/grep，或通过 Bash 调用单个 `python3 -I -S -c '...'` 命令。文件工具支持 `/workspace/...` 路径；命令使用相对路径，macOS 上没有真实的 `/workspace` 挂载点。派生进程、管道、后台命令和任意网络均未开放。

命令在私有副本中执行，原文件保持不变；新增/修改的结果保存到当前工作区 `artifacts/local/<job-id>/`，任务元数据记录相对路径。write/edit 工具只发布指定目标，导入的 upload 输入只读。符号链接、硬链接、设备文件拒绝进入副本，隐藏文件和配置文件排除。

当前每次输入最多 2000 个文件、64 MiB，目录深度最多 32 层；最多并行两项本地任务，每项最多 120 秒。stdout/stderr 分别保留 512 KiB，单文件写入上限 64 MiB；监督进程定期检查副本总量和条目数，这不是严格的磁盘配额或内存硬限制。最近任务副本保留有限历史，重启后遗留副本尚未自动清理。

开发模式继续使用现有登录界面与认证。正式打包模式是当前 macOS 用户的单用户本地应用，由每次启动随机生成的 loopback gate 保护本地 HTTP 服务，无需 bootstrap 密码。Web 服务和远程 MCP 的身份认证不受影响。

## 窗口与退出

- 红色关闭按钮：隐藏主窗口，后端继续运行；点击菜单栏 TCode 或 Dock 恢复。
- Cmd+Q 或菜单栏退出：停止本次启动的后端、sidecar 和进程组；不主动发送远程任务取消 API。
- 应用菜单可以打开运行数据目录、定位日志和重启本地服务。
- Cmd+R 重新加载界面，Cmd+1 显示主窗口；这两个是应用内快捷键，不是全局快捷键。
- 本阶段尚未验证任意本地工具自行脱离进程组后的退出清理；完整任务生命周期见后续阶段。

已提交远程任务不会仅因关闭桌面窗口被主动取消；远程服务自己的生命周期仍由其部署决定。现已接入持久化取消意图、后台核对和结果回收，详细覆盖范围与限制见本文末尾。

## 数据与日志

默认存放于 macOS `~/Library/Application Support/TCode Desktop/`：

```text
runtime/       本次桌面应用的业务数据与工作区
logs/backend.log
               本地后端启动与运行日志，仅当前用户可读写
```

因此默认不会自动显示旧 Web 实例的会话，也不会停止正在运行的 Web 服务。**不要同时让桌面和 Web 对同一运行根启动两个后台调度器。** 后续再做显式数据迁移和外部目录授权，不通过默认共用目录绕过。

可用 `TCODE_DESKTOP_RUNTIME=/absolute/path` 指定独立运行根。不要将它指向正在使用的 Web 运行根。

后端首次分配 loopback 端口，后续优先复用；被其他程序占用时自动换端口。使用桌面专用随机 HttpOnly cookie 和 Origin/Host 校验；源码模式沿用账号认证，冻结后端未显式覆盖时默认本机单用户模式。不能直接将该地址粘贴到普通浏览器访问。远程链接需用户确认后交系统应用打开，网页无 Node.js 或任意本机命令接口。

已保存会话位于后端存储，不依赖端口；浏览器本地草稿/布局依赖 origin。如果发生端口冲突并换端口，当前版本不会自动迁移旧 origin 的草稿与布局。

## 桌面界面与 Web 的关系

两端共享业务组件，桌面端使用独立的布局默认值、账号布局存储和样式。桌面导航按会话、工作区、知识、设置分组；默认隐藏重复活动栏、右侧面板和底部执行区，仍可通过布局菜单恢复。顶部次要操作集中到“更多操作”，所有既有功能路由保留。登录页使用桌面文案，仍需已配置的账号认证。

文件面板可选择或拖入本地文件，复制到本地后端工作区的 upload 目录。也可选择文件夹，确认文件数和大小后保留目录结构导入；默认跳过隐藏文件、node_modules、__pycache__，单文件上限 100 MB，一批最多 200 个文件、1 GB，不保留空目录。这是复制快照，不是任意外部文件夹的直接绑定。切换工作区停止剩余导入，已复制的文件保留。

桌面下载使用系统保存对话框；Finder/终端按钮由主进程核对当前账号的工作区后打开，不接受前端传入的任意本机路径或命令。任务终态通知已接入，点击可返回原会话；按账号在本地记录最近 1000 个已提醒事件，重开最多补发三条，其余保留在应用未读列表。系统是否实际显示横幅取决于 macOS 通知设置；不在通知中展示任务结果正文。全局快捷键通过“显示”菜单主动启用，默认不占用。

真实 Electron 集成检查现已覆盖登录后的工作台、创建测试工作区、目录结构文件导入/读回和原生目录接口权限。系统文件选择器、通知横幅点击、Finder/终端实际拉起仍需人工交互验收。桌面渲染进程隔离不等于本地工具执行的操作系统沙箱，后者由后端执行策略和系统权限分别控制。

## 取消与恢复的当前边界

异步任务列表的停止操作先把取消意图写入 Tracker 数据库，再使用已保存的远程 job_ref 调用 Job Protocol terminate_job。只有回执中的 job_id、process_id 和终态吻合才确认停止；远程已完成则保留完成和结果，但不再触发后续步骤。网络失败或无有效回执保留“取消待确认”，后台自动退避重试；退出后停止本地重试，重开后继续。

尚未领取的排队任务通过与领取共享的 SQLite 写事务直接取消。已经领取但尚无远程引用的任务显示“提交状态待核对”，不会自动重提，也不会宣称远程取消成功。此入口不向远程清单 PID 或持久化 execution_pid 发送本机信号。

流程停止先持久化 terminated 并冻结活动/排队步骤，再停止本地 worker，给同一所有者的关联远程任务写入取消意图。清理未完成时重启继续，旧步骤回写不能重新激活流程。

后台每 3 秒扫描本地管理的工作区，过期执行只查询已有远程引用；恢复操作有 SQLite 租约，失败按 2–60 秒退避。计算完成与文件传输分别记录，下载失败继续重试，已通过大小和 SHA-256 校验的文件直接复用；用户修改过的同名文件另存副本。单文件中断会重新下载该文件，不是 HTTP Range 续传。只有产物保存成功才允许工作流推进。系统唤醒会检查后端健康状态，失联时自动重启；后端重启后，本地 Workflow 从持久化阶段检查点有限重试，默认最多 3 次。显式取消和终止状态不会自动恢复。

这些改动针对现用 Symphony / SharedTracker 任务路径。统一 `/api/runtime/jobs` 未注册的取消适配器仍失败关闭；Workspace 删除链路、变更远程服务配置后的来源迁移、服务端幂等查询及下游 GPU/队列终止验收仍未覆盖。Job Protocol 的进程终止回执不能单独证明所有下游计算已停止。
